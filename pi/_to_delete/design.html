택트 스위치 1개로 도는 녹음 → 감정분석 → 답변 루프와 24구 WS2812 링의 상태 표현

01전체 구조

파이는 클라이언트만 합니다. 같은 공유기 아래에서 서버의 8000 포트로 POST를 걸고, 결과를 그 요청의 응답으로 바로 받습니다.

폴링은 필요 없습니다. HTTP는 요청과 응답이 한 쌍입니다. 파이가 requests.post()를 부르면 그 함수가 서버 처리가 끝날 때까지 기다렸다가 결과를 리턴값으로 돌려줍니다. 파이 쪽에 서버를 띄우거나 "다 됐나요?"를 반복해서 물어볼 이유가 없습니다. (폴링이 필요한 경우는 서버가 먼저 파이에게 말을 걸어야 할 때뿐입니다 — 예: 앱에서 원격으로 파이를 깨우기. 지금 설계엔 그런 흐름이 없습니다.) 파이 쪽 타임아웃만 넉넉히(analyze 60초, tts 90초) 잡아두면 됩니다.

02서버 API 3개가 왜 나뉘어 있나

한 번의 대화 턴에서 세 번 호출합니다. 각각 하는 일이 다르고 걸리는 시간도 다릅니다.

엔드포인트보내는 것받는 것하는 일
POST /api/v1/voice/analyze multipart
audio(wav) + session_id		 transcript
emotions{9}
pitch_mean/std		 SenseVoice로 받아쓰기 + emotion2vec로 감정확률 + pyworld로 피치. 셋을 동시에 돌림. 가장 오래 걸림
POST /api/v1/chat/reply JSON
transcript + emotions		 reply_text '뭉이' 시스템 프롬프트 + 이전 대화 기록으로 GPT 답변 생성. 감정을 프롬프트에 끼워 넣음
POST /api/v1/tts JSON
text + session_id		 audio/wav (바이너리) 답변 텍스트를 음성으로. 직전 감정에 맞춰 말투 지시문(instructions)을 자동으로 바꿈

세션 상태는 서버가 session_id로 메모리에 들고 있습니다. 그래서 파이는 매번 같은 session_id만 보내면 대화 맥락과 감정 누적이 알아서 이어집니다.

지금 서버엔 care_emotion이 없습니다. 서버가 주는 감정은 emotion2vec의 9개 (angry / disgusted / fearful / happy / neutral / other / sad / surprised / unknown)뿐입니다. 기획서의 care_emotion은 14개라 1:1 대응이 안 됩니다. 그래서 파이 쪽 care_map.py에서 SER 확률 + 전사 키워드 + 피치 세 신호를 합쳐 14개 중 하나로 좁힙니다. 서버를 안 고쳐도 되고, 나중에 서버로 그대로 옮겨도 되는 형태로 분리해 뒀습니다.

03상태 전이도

버튼은 하나, 상태는 다섯. 버튼의 의미는 현재 상태에 따라 달라집니다.

녹음이 0.6초 미만이면 실수로 두 번 누른 것으로 보고 버리고 READY로 돌아갑니다. 녹음 중 버튼을 안 누르면 30초에서 자동 종료합니다. 둘 다 config.py에서 조절합니다.

└── requirements.txt

08배선과 실행

WS2812 DINGPIO18 (핀 12)
WS2812 5V / GND외부 5V, GND는 파이와 공통
택트 스위치GPIO17 (핀 11) ↔ GND
마이크 / 스피커USB
sudo apt install -y alsa-utils python3-dev \
     portaudio19-dev libopenblas-dev

pip install -r requirements.txt

# 서버 주소 확인 (PC에서 ipconfig)
export MOONG_SERVER=http://192.168.0.10:8000

python3 audio_io.py        # 장치 번호 확인
sudo -E python3 led_controller.py   # 색상 눈으로 확인
sudo -E python3 main.py    # 실행
24구 × 최대밝기는 약 1.4A입니다. 파이 5V 핀에서 끌어오면 전압이 떨어져 재부팅이 걸립니다. LED는 별도 5V 어댑터로 먹이고 GND만 파이와 묶으세요. 지금 설정의 밝기(0.3~0.55)면 실사용은 0.5A 이하입니다.
왜 sudo -E 인가 — rpi_ws281x는 PWM/DMA 레지스터를 직접 건드려서 root가 필요합니다. -E를 빼면 MOONG_SERVER 같은 환경변수가 사라져 기본값(192.168.0.10)으로 붙습니다.
